- 审查日期：2026-11-23

## 一、总体结论

项目整体架构清晰，网络层、流代理、下载状态机、播放列表持久化都有明显的加固痕迹，现有 4 个测试套件全部通过（27.00 秒，148 个用例）。主要风险集中在两个位置：**探测对话框关闭后的网络回调生命周期**，以及**少数错误路径的用户可见行为与内容校验**。

| 等级 | 数量 | 结论 |
|---|---:|---|
| P0 | 0 | 未发现必然导致数据损坏、凭据泄露或普遍崩溃的问题 |
| P1 | 1 | `SourceProbe` 首页请求存在 use-after-free 路径，建议发布前修复 |
| P2 | 3 | 搜索播放错误误报、`octet-stream` 下载内容校验缺口、媒体地址 SSRF 风险面 |
| P3 | 8 | 阻塞、错误语义、隐私边界、损坏恢复、续传长度、测试稳定性等 |

### 发布门槛建议

- **P1 必须修复**：否则“探测中取消/关闭窗口”存在崩溃窗口。
- **P2 建议本迭代修复**：下载完整性和搜索错误提示会直接影响用户判断。
- **P3 可排期**：不影响主流程，但应在下一轮加固中处理。

## 二、问题清单

### P1-1 `SourceProbe` 首页请求回调捕获裸 `this`，对话框关闭后可 use-after-free

**位置**

- `src/net/SourceProbe.cpp:928`：`m_http->fetch(..., [this](QNetworkReply *reply) { ... })`
- `src/net/SourceProbe.cpp:807-815`：`Prober::~Prober()` 只 abort `m_activeReply`、`m_validator`、`m_webValidator`
- `src/net/SourceProbe.cpp:881-897`：`Prober::cancel()` 同样没有覆盖首页请求
- `src/net/HttpClient.cpp:255`、`:363-368`：回调由 `HttpClient` 作为接收者保存并执行，生命周期不跟 `Prober` 绑定
- `src/ui/SourceProbeDialog.cpp:156`：取消按钮连接的是 `reject()`，不是 `closeEvent()`
- `src/ui/SourceProbeDialog.cpp:209`：`new SourceProbe::Prober(m_http, this)`，`Prober` 是对话框子对象
- `src/ui/SourceManagerDialog.cpp:859`、`:935`：`SourceProbeDialog` 是栈对象，`exec()` 返回后立即析构

**证据链**

1. `SourceProbeDialog` 在“从网站添加搜索源”里以栈对象创建；用户点“取消”走 `reject()`，不会触发只处理窗口关闭的 `closeEvent()`。
2. `Prober::start()` 先调用 `fetchHome()`；`fetchHome()` 用 `[this]` 捕获 `Prober`，但没有把该 `QNetworkReply` 存入 `m_activeReply` 或其他成员。
3. `HttpClient::fetchInternal()` 把 `onReady` 回调挂在 `HttpClient` 自己的 `finished` 连接上；`HttpClient` 属于主窗口，生命周期远长于对话框。
4. `Prober` 析构时只 abort 候选请求、validator 和网页 validator，**首页请求不在清理范围内**。
5. 对话框析构后，首页请求仍可能完成；`HttpClient` 随后执行 `onReady(reply)`，访问已经析构的 `Prober` 成员，构成 use-after-free。

**影响**

- 触发条件真实存在：用户在“正在探测”阶段取消、按 Esc、直接关闭窗口，或对同一对话框再次点击“开始探测”导致旧 `Prober` 被 `deleteLater()`。
- 结果可能是崩溃、无响应或未定义行为；即使不立即崩溃，也会继续向已关闭的界面投递结果。
- 首页请求有 15 秒传输超时，因此关闭后仍有较长的迟到回调窗口。

**修复建议**

- 在 `Prober` 内保存 `QPointer<QNetworkReply> m_homeReply`，在 `cancel()` 和析构中 abort/deleteLater；或让 `fetchHome()` 走一个可返回 `QNetworkReply*` 的接口，而不是只注册回调。
- 回调同时捕获 `QPointer<Prober>` 作为兜底，进入回调先判断 `guard.isNull()`；为空时只清理解 `reply`，不再访问 `this`。
- 把“取消按钮”改为显式调用 `cancel()` 后再 `reject()`，不要只依赖 `closeEvent()`。
- 增加回归测试：构造一个延迟完成的假回复，在完成前析构 `Prober`，验证不崩溃、回复被 abort。建议在 Debug/ASAN 下跑一次。

**证据等级**：代码路径静态确证；未做运行时崩溃复现，因此不宣称“已经发生过线上崩溃”。

### P2-1 搜索条目成功播放后，中途错误仍弹“这个搜索条目没有返回可播放的内容”

**位置**

- `src/ui/MainWindow.cpp:772`：播放搜索结果时设置 `m_pendingSearchPlayIdentity`
- `src/ui/MainWindow.cpp:178-184`：只有切到**不同条目**时才清除 pending
- `src/ui/MainWindow.cpp:185-200`：`errorOccurred` 只要当前条目 identity 与 pending 相同，就弹“无法播放搜索结果 / 这个搜索条目没有返回可播放的内容”

**问题**

`m_pendingSearchPlayIdentity` 在成功播放后没有清除。用户从搜索结果播放一首歌，正常播放数分钟后遇到网络抖动、CDN 断流或解码错误，`QMediaPlayer` 仍会发 `errorOccurred`；当前条目 identity 与 pending 相同，于是弹出“这个搜索条目没有返回可播放的内容”。这条文案描述的是“启动阶段没有可播放地址”，与实际“播放中途失败”不符，也会让用户误以为搜索源完全不可用。

**修复建议**

- 在播放真正开始后清除 pending：监听 `playbackStateChanged == Playing` 且 `position > 0`（或超过 1–3 秒）时清除；或在 `QMediaPlayer::mediaStatusChanged` 进入 `LoadedMedia/BufferedMedia` 且已开始播放后清除。
- 如果产品希望保留“启动失败”提示，把弹窗限制在 `m_playAttemptStarted == false` 的启动阶段；中途错误走普通状态栏/播放器错误提示，文案改为“播放中断，可重试或换源”。
- 增加 UI 逻辑测试：先模拟成功播放，再模拟同一 identity 的 `errorOccurred`，断言不出现“没有返回可播放的内容”弹窗。

### P2-2 `application/octet-stream` 下载绕过首块魔数校验，HTML/JSON 错误页可能被当成媒体保存

**位置**

- `src/download/DownloadTask.cpp:1390-1412`：`isMediaContentType()` 对 `mime.contains("octet-stream")` 直接返回 `true`
- `src/download/DownloadTask.cpp:437-438`：`m_verifyMediaMagic` 只在 Content-Type 为空或 `text/plain` 时启用
- `src/download/DownloadTask.cpp:1434-1455`：`looksLikeMediaPayload()` 负责识别 `#EXTM3U`、`<`、`{`、`[` 等非媒体前缀
- `src/download/DownloadTask.cpp:1088-1093`：完成时只校验长度，没有再次校验内容

**问题**

服务器返回 `Content-Type: application/octet-stream`、URL 又带 `.mp3`/`.mp4` 后缀时：

1. `isMediaContentType()` 放行，进入直链媒体下载；
2. `m_verifyMediaMagic` 为 `false`，`looksLikeMediaPayload()` **根本不会被调用**；
3. 响应正文即使是 HTML 错误页或 JSON 错误对象，也会按媒体写入临时文件；
4. 只要长度与 Content-Length 一致，就会提交为最终文件。

**影响**

用户看到“下载完成”，但文件无法播放；对批量下载和弱网环境更容易出现。该问题不是路径穿越，也不是远程代码执行，但属于明确的内容完整性缺陷。

**修复建议**

- `m_verifyMediaMagic` 增加 `contentType.startsWith("application/octet-stream")` 分支；对未知二进制类型至少校验首块。
- `looksLikeMediaPayload()` 在 `trimmed()` 前先剥离 UTF-8 BOM，避免 `\xEF\xBB\xBF<...` 绕过 `<` 判断。
- 如果首块无法识别且 URL 只有“媒体后缀”没有可信魔数，建议按失败处理，而不是仅凭后缀放行；私有封装确实没有稳定魔数时，可在配置中显式允许。
- 增加测试：伪造 `200 + application/octet-stream + HTML/JSON 正文 + .mp3 URL`，断言进入失败路径且不提交最终文件。

### P2-3 媒体地址只校验 http(s) 与 host，存在访问回环/内网地址的 SSRF 风险面

**位置**

- `src/net/MaccmsWebProvider.cpp:145-159`：`encodeMediaUrl()` 只拒绝非 http(s)，不拒绝 `127.0.0.1`、`169.254.169.254`、私有网段、`localhost`
- `src/stream/StreamProxy.cpp`：拿到地址后注册 token 并发起上游请求
- `src/util/HeaderPolicy.h:145-177`：跨 host 时会裁掉敏感头，但普通请求头仍可能发送

**问题**

远程网页/JSON 可以返回任意 http(s) 媒体地址；程序会把它当作可播放/可下载地址，通过本地代理实际发起 GET。跨 host 时 `Authorization`/`Cookie` 会被裁剪，这是正确的；但请求仍会到达回环或内网服务，可能触发路由器管理页、云元数据端点或内网服务的 GET 副作用。当前没有证据表明已被利用，按“安全风险面”记录，而不是已确认漏洞。

**修复建议**

- 在媒体地址进入 `StreamProxy` / `DownloadTask` 前做地址策略校验：拒绝回环、链路本地、私有网段、组播和未指定地址；对域名做 DNS 解析后再校验一次，避免 DNS rebinding。
- 如果产品确实需要局域网源，提供显式“允许内网源”开关，默认关闭，并在 UI 说明风险。
- 不要把该校验只放在 HTML 解析层；下载、播放、代理三条入口都要覆盖。

## 三、P3 问题与加固项

### P3-1 播放列表写入在主线程重试，最坏约 160ms UI 阻塞

`src/core/PlaylistStore.cpp:57-76` 在 `writeFile()` 内做 3 次尝试，前两次失败后 `QThread::msleep(80)`；最坏约 160ms。`PlaylistController::save()` 可能在自动保存、退出保存或用户手动保存时从 GUI 线程调用。

影响：磁盘被占用/杀毒软件扫描时，界面短时卡顿；失败时还会叠加状态栏提示。建议把写盘移到工作线程，或至少改为异步重试，不在 GUI 线程 sleep；同时保留“失败不丢修改、可重试”的现有语义。

### P3-2 `MediaRemux` 成功时仍把 ffmpeg 日志写进 `error`

`src/download/MediaRemux.cpp:159-169` 先计算 `success = normal && outputOk && !m_timedOut`，随后 `else if (!log.isEmpty()) error = log.right(2000)`；当转码成功但 ffmpeg 在 stderr 打了警告时，`finished(true, path, error)` 仍携带非空错误文本。

当前 `DownloadManager` 只看 `ok`，所以用户侧不致命，但错误语义不正确，后续若把 `error` 展示到 UI 或日志会出现“成功但带错误”的歧义。建议只在 `!success` 时填充 `error`，或把日志拆成独立的 `log` 参数。

### P3-3 `HeaderPolicy::isSensitiveHeader()` 漏掉 `X-APIKEY`、`apiKey` 等无连字符写法

`src/util/HeaderPolicy.h:14-30` 只精确匹配 `x-api-key`、`api-key`、`access-key`，以及包含 `token/secret/session/credential` 或以 `-key/-auth` 结尾的名称。`X-APIKEY` 归一化为 `x-apikey`，既不是精确值，也不以 `-key` 结尾，会被判为不敏感。

影响：自定义源使用 `X-APIKEY`/`apiKey` 时，跨 host 请求不会裁剪，且可能以明文写入源配置/日志。建议归一化时去掉 `-`/`_` 再比较，或补充 `apikey`、`x-apikey`、`api_key` 等变体。`Referer` 按当前设计不被视为敏感头，跨 host 仍会发送；如果 Referer 含查询串，需确认是否接受该隐私边界。

### P3-4 源配置损坏恢复会重新播种内置源，用户自定义源从活动配置中消失

`src/net/SourceRegistry.cpp:355-381` 在 `sources.json` 解析失败且备份成功后，直接 `m_sources = seedSources(); save()`。

原文件被改名为 `.corrupt-*` 备份，`m_lastError` 会提示备份文件名，数据没有立即永久丢失；但用户自定义源不会自动合并回来，活动配置只剩内置源。建议在报告中作为“恢复策略风险”：UI 明确提示备份路径，并提供“从备份导入/合并”的入口，而不是只提示“已恢复预置源”。

### P3-5 无 Content-Length/无总长的续传响应缺少最终长度校验

`src/download/DownloadTask.cpp:1088-1093` 只在 `m_expectedBytes >= 0` 时比较写入字节数；`parseContentRange` 对 `bytes a-b/*` 输出 `total=-1` 时，`m_expectedBytes` 可能保持 `-1`。

影响：源站不返回总长、连接被截断但 Qt 未报告网络错误时，可能留下不完整文件。建议对 `m_expectedBytes < 0` 的直链下载在完成时至少校验 `Content-Range` 终点、临时文件非零和首块魔数；能拿到总长时一律强制精确匹配。

### P3-6 `PlaybackController` 的同步等待与 GUI 阻塞点

- `src/core/PlaybackController.cpp:343-349`：`playRowInternal()` 用 `Qt::BlockingQueuedConnection` 调 `StreamProxy::proxyUrlFor`。代理线程若正在处理网络回调、缓存落盘或大分片，GUI 会同步等待。
- `src/core/PlaybackController.cpp:201-211`：析构时 `wait(3000)`；若代理线程 3 秒未退出，会摘掉父子关系并依赖 `finished → deleteLater` 自回收。退出路径可能短时卡顿，且 GUI 事件循环已结束时 `deleteLater` 不保证执行。

当前代码有注释说明这是有意权衡，未观察到实际崩溃；建议作为生命周期/性能风险记录，后续可把 token 注册改成无阻塞的异步接口，并给线程退出增加明确的兜底回收策略。

### P3-7 `MusicVisualWidget`、频谱与缓存探测的性能观察项

- `MusicVisualWidget` 以约 30fps 全窗口自绘，包含抗锯齿、渐变和 46 根频谱柱；音乐播放时 CPU 可能偏高。
- `AudioSpectrumAnalyzer` 每 33ms 在 GUI 线程做 2048 点 FFT，并对每个音频 buffer 逐帧混音；高采样率/多声道时需要注意 `QAudioBufferOutput` 队列积压。
- `LyricsCache` / `MediaCache` 的候选路径探测最多约 1000 次 `QFileInfo`，在大量缓存条目时可能拖慢列表操作。

这些不是已证实缺陷，建议先用 profiler 建立基线，再决定是否把 FFT 移到工作线程、降低重绘频率或给候选探测加索引；不要在没有测量数据时直接改算法。

### P3-8 测试覆盖广，但缺少本轮三个高风险路径的回归用例

现有 4 个套件、148 个用例全部通过：`test_core_logic` 69、`test_integration` 41、`test_storage` 27、`test_ui_logic` 11。真实网络探针已用 `MVP_LIVE_PROBE` / `MVP_REAL_APPLE_HLS` 门控，默认跳过，这是正确的。

缺口：

- 没有“探测中析构 `Prober`”的生命周期测试；
- 没有“搜索条目成功播放后中途报错”的 UI 逻辑测试；
- 没有“`application/octet-stream` + HTML/JSON 正文 + 媒体后缀”的下载拒绝测试；
- `mvp_integration` 曾出现“全量并发失败、单独运行通过、再全量通过”的偶发超时，属于时间敏感抖动，建议在报告中标注为 CI 稳定性问题，而不是产品缺陷。

## 五、值得保留的正面设计

以下设计在审查中确认有效，建议后续重构不要破坏：

- `HttpClient`：拒绝 CRLF 头注入；手动处理重定向并逐跳清洗敏感头；`sourceOrigin` 限定凭据作用域；URL 脱敏；累计响应字节上限。
- `DownloadTask`：416 作为“已下载完成”处理；临时文件长度截断；HTML/网页伪装拒绝；HLS 加密拒绝；`BYTERANGE`、`EXT-X-MAP`、`EXT-X-BASE` 处理；无 `ENDLIST` 时需确认。
- `StreamProxy`：token 路径作用域与同源校验；m3u8 忽略 Range；单文件 fMP4 不建整段缓存；LRU 淘汰；缓存文件句柄及时释放；关闭时先断开回调再 abort。
- `PlaylistStore`：主文件 + 快照恢复；`ReadError/TooLarge/Corrupt` 阻断保存，避免空模型覆盖可恢复文件；损坏文件改名备份并保留最近 5 份。

- `AudioSpectrumAnalyzer`：格式校验、空闲全零、attack/release 平滑。
