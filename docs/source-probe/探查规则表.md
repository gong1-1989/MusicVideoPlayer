# 网站探查规则表（影视 / 音乐）

版本：2026-11-23
对应代码：`src/net/SourceProbe.cpp`、`src/net/SourceProbe.h`
说明：本表由当前实现和真实节点验证结果导出，不是新增逻辑；路径、参数、校验和失败提示均与代码一致。第 1-8 节是影视规则，第 9-14 节是音乐规则。

## 1. 总规则表

| 编号 | 类别 | 触发条件 | 处理规则 | 结果/提示 |
| --- | --- | --- | --- | --- |
| R01 | 输入 | URL 不是 http/https | 不发起探测 | `网址无效，必须以 http:// 或 https:// 开头` |
| R02 | 输入 | URL 没有路径 | 补 `/` 后作为站点首页 | 进入首页抓取 |

| R04 | 输入 | 用户地址带固定示例关键词 | 把 `wd/q/query/search/term/name/searchTerm/keyword/filter` 的固定值替换为 `{keyword}`；音乐按接口族继续补参数 | 可继续作为搜索源验证 |

| R07 | 输入 | 地址是 `/index.php/ajax/data` | 补 `mid=1`、`limit={limit}`、`wd={keyword}` | 适配 MacCMS Ajax 接口 |
| R08 | 输入 | 用户自定义路径或首页线索 | 与内置路径合并、去重 | 同一地址只试一次 |
| R09 | 首页 | 首页返回 2xx | 读取 `<title>` 作为站点名；扫描 HTML/JS 中的接口线索 | 线索优先于内置路径 |
| R10 | 首页 | 首页返回 401/403 | 记录“拒绝访问” | 不因首页失败停止接口探测 |
| R11 | 首页 | 首页 301/302 跳转 | 保存跳转后的域名作为备用 origin | 先试用户输入域名，再试跳转域名 |
| R12 | 首页 | 首页同时出现 JSON 和 XML 线索 | JSON 线索排前，`/at/xml/` 排最后 | 避免先浪费一次 XML 请求 |
| R13 | 候选 | 用户明确接口 | 第 1 优先级 | 用户填什么先试什么 |
| R14 | 候选 | 首页 JSON 线索 | 第 2 优先级 | 覆盖 `/from/xxx/`、`/inc/api.php` 等非标准路径 |
| R15 | 候选 | 首页 XML 线索 | 第 3 优先级，仅诊断 | 当前不解析 XML，只用于解释失败原因 |
| R16 | 候选 | 用户自定义路径 | 第 4 优先级 | 支持完整 URL 或相对路径 |
| R17 | 候选 | 内置影视路径 | 第 5 优先级 | 共 10 条，见第 2 节 |
| R18 | 候选 | 自动识别开启 | 再追加另一种类型的默认路径 | 用户选错类型时可纠正 |
| R19 | 候选 | 相对路径 | 先拼用户输入 origin，再拼跳转 origin | 域名优先，避免 301 浪费预算 |
| R20 | 请求 | 单次请求 | 6 秒超时；影视总预算 24 秒，音乐 32 秒，自动识别 40 秒 | 超时进入下一候选 |
| R21 | 请求 | 尝试次数 | 普通 16 次，自动识别 20 次；音乐 16 条内置路径占满普通上限 | 首页线索和自定义路径会额外增加次数 |
| R22 | 请求 | 响应正文 | JSON 上限 2 MB；HTML 上限按 `NetLimits::kHtmlBytes` | 超限记“响应过大” |

| R25 | 格式 | 正文以 `<?xml`、`<rss`、`<list` 开头 | 归类为 XML 接口 | 提示当前只解析 JSON |
| R26 | 格式 | JSON 解析失败 | 归类为“返回的不是 JSON” | 提示直接填接口地址 |
| R27 | 结构 | JSON 里没有非空对象数组 | 归类为“JSON 没有结果数组” | 提示可能只支持分类/列表参数 |
| R28 | 结构 | 有数组但找不到标题字段或播放字段 | 归类为“字段猜不出” | 提示需要手动配置字段映射 |

| R32 | 识别 | 音乐特征 | `artist`、`track`、`album`、`song`、`previewurl`、`url_resolved`、`listen_url`、`stream.url`、`upload_name`、`.mp3/.m4a/.flac/.aac/.ogg/.wav/.opus` | 判定为音乐 |
| R33 | 识别 | 两边都没有特征 | 用候选路径自带的类型兜底 | 不因无法判断而失败 |
| R34 | 校验 | 地址不含 `{keyword}` | 直接跳过该候选 | 不保存固定地址 |
| R35 | 校验 | 第一轮试搜 | 影视用 `电影`，音乐用 `love` | 请求 10 条 |
| R36 | 校验 | 第一轮无结果 | 换下一个候选 | 记录“试搜没有结果” |
| R37 | 校验 | 第一轮有结果 | 进入第二轮 | 保存首轮结果用于比对 |
| R38 | 校验 | 第二轮试搜 | 影视用 `电视剧`，音乐用 `jazz` | 请求 10 条 |
| R39 | 校验 | 两轮标题集合完全相同 | 判定“接口忽略关键词，只返回固定列表” | 不保存为搜索源，换下一个候选 |
| R40 | 校验 | 第二轮请求失败或无结果 | 保留首轮结果并接受 | 避免网络抖动误杀 |
| R41 | 校验 | 第二轮标题集合不同 | 判定关键词生效 | 接受该配置 |
| R42 | 保存 | 配置生成 | `urlTemplate` 为绝对地址，`itemsPath` 为实际数组路径，`streamKind` 为 `direct`/`episodes`；Subsonic/Navidrome 的 `streamUrl` 可以是 `@https://host/rest/stream?id={id}&u=...` 模板 | `enabled=true`，等待用户确认写入 |
| R43 | 保存 | 请求头 | 默认带输入站点的 `Referer` | 兼容需要防盗链的站点 |
| R44 | 保存 | 源 ID | `site_<host下划线>_<sha1(origin+sitePath)前8位>` | 同 host 多接口不会互相覆盖 |
| R45 | 失败 | 401/403 次数 > 0 | 优先提示“站点拒绝程序访问” | 换路径没用，音乐源需要账号/API key |
| R45a | 失败 | Subsonic/Navidrome 返回 `status=failed` | 提示“音乐接口认证失败” | 填带 u/p 或 token 的地址 |

| R47 | 失败 | XML 次数 > 0 | 提示“当前只解析 JSON” | 有 `/at/json/` 就换 JSON，否则手动配置 |
| R48 | 失败 | 连接失败且首页打不开 | 提示“站点连不上” | 检查本机网络/域名 |
| R49 | 失败 | JSON 无结果数组且无 404/非 JSON | 提示“可能只支持分类/列表参数” | 不是路径错，可能是参数名不是 `wd` |
| R50 | 失败 | 字段猜不出且无 404 | 提示“字段命名不标准” | 需要手动字段映射 |
| R51 | 失败 | 返回网页且无 404 | 提示“填接口地址” | 给 `/api.php/provide/vod/` 示例 |
| R52 | 失败 | 首页能开但候选全 404 | 提示“可能只有网页、没有采集接口” | 要求用户提供接口地址 |
| R53 | 失败 | 以上都不命中 | 通用提示“可能不是标准 JSON 接口” | 不猜测、不半成品落库 |

## 2. 内置影视路径表

所有路径都带 `{keyword}` 和 `wd=`；没有关键词占位符的路径不会进入候选。

| 序号 | 路径模板 | 用途 | 说明 |
| --- | --- | --- | --- |
| 1 | `/api.php/provide/vod/?ac=detail&wd={keyword}` | 标准详情搜索 | 23 个真实可搜索节点的有效路径 |
| 2 | `/api.php/provide/vod/?ac=videolist&wd={keyword}` | 兼容旧版列表参数 | 部分老 MacCMS |
| 3 | `/api.php/provide/vod/?ac=list&wd={keyword}` | 兼容列表搜索 | 必须带 `wd`，不能用无关键词版本 |
| 4 | `/api.php/provide/vod/at/json/?ac=detail&wd={keyword}` | 强制 JSON 输出 | 首页只给 XML 时优先试这条 |
| 5 | `/index.php/ajax/data?mid=1&wd={keyword}&limit={limit}` | MacCMS Ajax 数据接口 | 参数用 `mid/limit/wd` |
| 6 | `/inc/api.php?ac=detail&wd={keyword}` | 老版 inc 接口 | 无 `provide/vod` 路径 |
| 7 | `/inc/api_mac10.php?ac=detail&wd={keyword}` | MacCMS10 采集接口 | 常见于资源站 |
| 8 | `/inc/api_mac_m3u8.php?ac=detail&wd={keyword}` | 只给 m3u8 的采集接口 | 播放字段通常是 m3u8 |
| 9 | `/api.php/provide/vod?ac=detail&wd={keyword}` | 不带尾斜杠 | 部分站点对尾斜杠敏感 |
| 10 | `/api.php/provide/vod/?wd={keyword}` | 只给关键词 | 让站点用默认 `ac` |

不进入内置路径的形态：

| 形态 | 原因 | 获取方式 |
| --- | --- | --- |
| `/api.php/provide/vod/from/xxx/` | `from` 是按资源站模块区分的，不能统一枚举 | 首页线索或用户直接填写 |
| `/api.php/provide/vod/?ac=list` | 不带关键词，必然“有结果但搜索无效” | 明确禁止 |
| `/at/xml/` | 当前只解析 JSON | 只做诊断，不保存 |
| 纯网页搜索页 | 返回 HTML，不是采集接口 | 提示用户提供接口地址 |

## 3. 首页接口线索表

从首页 HTML/JS 中抓取，最多保留 10 条，按出现顺序去重，然后 JSON 线索排前、XML 线索排后。

| 线索类型 | 匹配形态 | 后续处理 |
| --- | --- | --- |
| 标准采集 | `/api.php/provide/vod...` | 补 `ac=detail&wd={keyword}` |
| 优化采集 | `/api.php/provide/vod/from/<模块>/` | 保留 `from` 路径，再补 `wd` |
| JSON 输出 | `/api.php/provide/vod/at/json/` | 优先于 XML |
| XML 输出 | `/api.php/provide/vod/at/xml/` | 排最后，仅诊断 |
| inc 接口 | `/inc/api.php`、`/inc/api_mac10.php`、`/inc/api_mac_m3u8.php` | 补 `ac=detail&wd={keyword}` |
| Ajax 接口 | `/index.php/ajax/data` | 补 `mid=1&limit={limit}&wd={keyword}` |

## 4. 试搜校验表

| 阶段 | 请求 | 判定 | 不通过时 |
| --- | --- | --- | --- |
| 前置 | 检查 `urlTemplate` 是否含 `{keyword}` | 不含直接跳过 | 不保存固定列表地址 |
| 第一轮 | `电影` / `love`，10 条 | 有结果才继续 | 无结果、报错都换候选 |
| 第二轮 | `电视剧` / `jazz`，10 条 | 与第一轮标题集合比较 | 完全相同则判定忽略关键词 |
| 第二轮异常 | 请求失败或无结果 | 不否定首轮 | 保留首轮结果并接受 |
| 接受 | 标题集合不同 | 关键词生效 | 生成配置，等待用户确认 |

标题集合比较规则：

1. 两轮都非空；
2. 条数相同；
3. 第一轮每个标题都能在第二轮找到；
4. 以上全部成立 → 视为同一批固定列表。

## 5. 失败归类优先级表

`diagnoseFailure` 按以下顺序返回，先命中先返回：

| 优先级 | 条件 | 用户提示 | 用户动作 |
| --- | --- | --- | --- |
| 1 | 401/403 次数 > 0 | 站点拒绝程序访问 | 换访问方式，不要继续换路径 |
| 2 | Subsonic/Navidrome `status=failed` | 音乐接口认证失败 | 填带 u/p 或 token 的地址 |
| 3 | 未授权次数 > 0 | IP 未授权/已到期 | 后台授权当前 IP 或换域名 |
| 4 | XML 次数 > 0 | 当前只解析 JSON | 换 `/at/json/` 或手动配置 |
| 5 | 连接失败 > 0 且首页打不开 | 站点连不上 | 检查网络/域名 |
| 6 | JSON 无结果数组，且无 404/非 JSON | 可能只支持分类/列表参数 | 确认参数名是否为 `wd`（音乐为 `query/q/name/searchTerm`） |
| 7 | 字段猜不出，且无 404 | 字段命名不标准 | 手动配置字段映射 |
| 8 | 返回网页，且无 404 | 填的是网页不是接口 | 改填 `/api.php/provide/vod/` 或音乐 API |
| 9 | 首页能开但候选全 404 | 可能只有网页、没有采集接口 | 向站点要接口地址 |
| 10 | 以上都不命中 | 可能不是标准 JSON 接口 | 手动配置 |

## 6. 字段映射表

| 目标字段 | 匹配顺序 | 约束 |
| --- | --- | --- |
| 标题 | `vod_name` → `trackname` → `track_name` → `upload_name` → `songname` → `song_name` → `song` → `title` → `name` | 先顶层精确，再嵌套路径；文本字段不能全是数字 |
| 播放地址 | 音乐只认 http(s)：`url_resolved`、`stream.url`、`previewUrl`、`preview_url`、`download_url`、`listen_url`、`playurl`、`play_url`、含音频后缀的 URL；影视按后缀/`$$$` | 音乐不能用 Subsonic 的本地 `path`；区分 `direct` / `episodes` |
| 作者/演员 | `artistname` → `artist` → `artist.name` → `uploader` → `singer` → `author` → `vod_actor` → `performer` | 文本字段不能全是数字 |
| 封面 | `vod_pic` → `pic` → `cover` → `cover_xl` → `album.cover` → `artworkurl100` → `artwork_url` → `image_url` → `poster` → `thumb` → `thumbnail` → `image` | 不能与标题/播放字段重复 |
| 年份 | `vod_year` → `year` | 不能重复 |
| 地区 | `vod_area` → `area` → `region` → `country` | 不能重复 |
| 分类 | `vod_class` → `class` → `cate` → `category` → `genre` → `type` | 不能重复 |
| 简介 | `vod_content` → `content` → `intro` → `desc` → `description` → `summary` | 不能重复 |
| 详情页 | `detail` → `weburl` → `web_url` → `pageurl` → `page_url` → `permalink` → `file_page_url` → `link` | 不能重复 |

匹配顺序：先字段名完全相等，再字段名包含关键词。嵌套字段按 `a.b`、`a[0].b` 形式保存到 `fields`。

## 8. 硬边界

| 边界 | 当前行为 |
| --- | --- |
| 只支持 JSON | XML 只归类，不解析 |
| 不保存直链 | 结果文件只记录状态、格式、字段是否存在、耗时 |
| 不猜测 | 字段猜不出、结构不认识就失败，不落半成品配置 |
| 不内置 catalog-only | 两轮关键词相同或无关键词才成功，都不保存 |
| 不统一枚举 `from/xxx/` | 只从首页线索或用户输入获得 |
| `Content-Type` 不可信 | 多个真实接口返回 `text/html` 但正文是 JSON，按正文判断 |

## 9. 音乐 150 节点采集与验证

口径与影视一致：每个节点都是一条接口 URL，不是站点首页；候选同时包含带 `{keyword}` 的搜索接口、catalog-only 接口、XML 和 HTML 入口。`music-nodes.json` 只保存接口 URL、字段名和验证统计，不保存歌曲标题、播放地址或任何账号凭据。

- 采集：10 轮，每轮 15 个，共 150 个候选节点。
- 验证：逐节点真实 HTTP 请求，首轮 `love`、二次 `jazz`，请求 10 条；连续两次标题集合完全相同才判定“忽略关键词”。
- 数据：`docs/source-probe/music-nodes.json`、`docs/source-probe/music-probe-results.json`。
- 脚本：`tools/source-probe/collect_music_nodes.ps1`、`tools/source-probe/probe_music_nodes.ps1`。

总统计（150 个节点）：

| 指标 | 数量 | 说明 |
| --- | --- | --- |
| total | 150 | 10 轮 × 15 |
| httpOk | 64 | HTTP 2xx，包含 JSON/XML/HTML/认证失败正文 |
| json | 36 | 可解析 JSON |
| auth | 21 | 401/403 或认证失败 |
| connection | 39 | DNS/超时/连接中断 |
| html | 18 | 返回网页/播放器 |
| xml | 4 | 返回 XML（Subsonic 默认格式） |
| noArray | 4 | JSON 无结果数组 |
| noStream | 16 | 有结果但无可播放字段 |
| serverError | 2 | 5xx |
| 404 | 20 | 按逐条结果统计 |
| empty | 9 | 2xx 但正文为空 |
| notJson | 1 | 正文不是 JSON/XML/HTML |
| searchable | 24 | 二次关键词校验通过 |
| directPlayable | 16 | 有 http(s) 直链字段 |

## 10. 音乐内置路径表

音乐共 16 条内置路径，顺序按“成功率/成本”排列；所有路径必须带 `{keyword}`。

| 序号 | 路径模板 | 用途 | 真实验证依据 |
| --- | --- | --- | --- |
| 1 | `/search?term={keyword}&media=music&limit={limit}` | iTunes 搜索 | 5→5，`trackName`/`previewUrl` |
| 2 | `/rest/search3?query={keyword}&songCount={limit}&f=json` | Subsonic/Navidrome v3 | 5→1，可搜索但只有 id |
| 3 | `/rest/search2?query={keyword}&songCount={limit}&f=json` | Subsonic v2 | 5→1 |
| 4 | `/rest/search?query={keyword}&songCount={limit}&f=json` | Subsonic 旧版 | 兼容老服务 |
| 5 | `/api/v1/tracks/?q={keyword}&page_size={limit}` | Funkwhale 曲目 | 匿名 401/404，未验证带凭据可用；保留给用户填写 |
| 6 | `/api/v1/albums/?q={keyword}&page_size={limit}` | Funkwhale 专辑 | 同上 |
| 7 | `/api/v1/artists/?q={keyword}&page_size={limit}` | Funkwhale 艺术家 | 同上 |
| 8 | `/api/v2/albums?q={keyword}` | Funkwhale v2 | 同上 |
| 9 | `/json/stations/search?name={keyword}&limit={limit}` | Radio Browser 按名称 | 5→5，`url_resolved` |
| 10 | `/json/stations/byname/{keyword}?limit={limit}` | Radio Browser 路径式名称搜索 | 5→5 |
| 11 | `/api/query?f=json&search={keyword}&limit={limit}` | ccMixter | 5→5，`files[0].download_url` |
| 12 | `/Items?searchTerm={keyword}&IncludeItemTypes=Audio&Limit={limit}` | Jellyfin 音频 | 匿名 401，需 API key |
| 13 | `/wp-json/wp/v2/search?search={keyword}&per_page={limit}` | WordPress 音乐媒体 | 4 个站点可搜索，但无音频直链 |
| 14 | `/api/search?q={keyword}&limit={limit}` | 通用音乐 API | 兜底 |
| 15 | `/search?q={keyword}&limit={limit}` | 通用搜索页 | 兜底 |
| 16 | `/ajax/search?keyword={keyword}&limit={limit}` | 通用 Ajax | 兜底 |

参数归一规则：

| 规则 | 触发 | 处理 |
| --- | --- | --- |
| M01 | 音乐路径没有 `{keyword}` | 把已有 `q/query/search/term/name/searchTerm/keyword/w/s` 的固定值替换为 `{keyword}`；都不存在时补 `q={keyword}` |
| M02 | Subsonic `/rest/search*` | 必有 `query={keyword}`、`songCount={limit}`、`f=json`；`f=xml` 强制改为 `f=json` |
| M03 | Radio Browser `stations/search` | 补 `name={keyword}`、`limit={limit}`、`hidebroken=true` |
| M04 | Radio Browser `byname` | 路径里已带关键词，只补 `limit` |
| M05 | ccMixter `/api/query` | 补 `f=json`、`search={keyword}`、`limit={limit}` |
| M06 | Funkwhale `/api/v1/*` | 补 `q={keyword}`、`page_size={limit}` |
| M07 | Jellyfin `/Items` | 补 `searchTerm={keyword}`、`IncludeItemTypes=Audio`、`Limit={limit}` |
| M08 | WordPress `/wp-json/wp/v2/search` | 补 `search={keyword}`、`per_page={limit}` |
| M09 | 音乐路径已有 `term` | 不再补 `q`，避免 iTunes 同时收到 `term` 和 `q` |
| M10 | 音乐内置路径带 `wd=` | 内置音乐路径不使用影视 `wd`；用户自带 `wd` 会保留，但音乐关键词以 `query/q/search/name/searchTerm` 为准 |

## 11. 音乐字段与播放模板

| 规则 | 场景 | 处理 |
| --- | --- | --- |
| M11 | 标题在嵌套对象 | 展开 `a.b`、`a[0].b` 路径；例如 `album.name`、`artists[0].name`、`group[0].songname` |
| M12 | 标题字段同名 | 先顶层精确匹配 `name`/`songname`，再匹配嵌套；避免 `artists[0].name` 抢在歌曲 `name` 前面 |
| M13 | 直链字段 | 认 `url_resolved`、`stream.url`、`previewUrl`、`download_url`、`listen_url`，不强依赖 `.mp3` 后缀 |
| M14 | 非 URL 的 `path`/`orig_filename` | 不当作播放地址；Subsonic 的 `path` 是本地文件路径 |
| M15 | 普通 `url` | 只有值含音频后缀或 `/listen/`、`/stream/` 才当直链，避免把详情页当播放地址 |
| M16 | Subsonic/Navidrome 只有 id | 生成 `@https://host/rest/stream?id={id}&u=...&p=...&v=...&c=...`，保留 u/p/t/s/v/c |
| M17 | 公开 demo 凭据 | 不写进内置默认配置；只允许用户在接口地址里自带 |
| M18 | XML 响应 | 当前不解析；Subsonic 必须加 `f=json` |
| M19 | 电台镜像 | 本次 `de1/de2.api.radio-browser.info` 可用，`nl1/at1/fr1/uk1/us1` DNS 不通；内置只用 de 系列 |
| M20 | 试听字段 | iTunes `previewUrl` 通常只有几十秒，当前按 `direct` 保存，不代表完整曲目 |
| M21 | 同一对象同时有 `url` 和 `url_resolved` | 优先 `url_resolved`；`url` 可能只是跳转地址 |
| M22 | 用户已选音乐，结果流是 `.m3u8` | 不因 HLS 后缀改判影视；电台/音乐 HLS 仍按音乐保存 |

## 12. 音乐失败归类优先级

| 优先级 | 条件 | 提示 |
| --- | --- | --- |
| 1 | 401/403 | 音乐服务需要用户名密码/API key，不是路径问题 |
| 2 | Subsonic `status=failed` | 认证失败；填带 u/p 或 token 的地址 |
| 3 | 未授权/已到期 | 需要有效 API key/账号 |
| 4 | XML | Subsonic 加 `f=json`；当前只解析 JSON |
| 5 | 连接失败且首页打不开 | 检查网络/域名；境外 API 可能被拦截 |
| 6 | JSON 无结果数组 | 可能 Subsonic 认证失败，或参数名不是 query/q/name/searchTerm |
| 7 | 有数组但无播放字段 | 只有 id 用 `/rest/stream` 模板；Jellyfin 用 `/Audio/{id}/stream` |
| 8 | 返回网页/播放器 | 填的是网页不是 API，给 `/rest/search3?f=json` 等示例 |
| 9 | 首页能开但候选全 404 | 可能只有网页，没有公开音乐 API |
| 10 | 以上都不命中 | 需要手动配置或带认证地址 |

## 14. 音乐硬边界

| 边界 | 当前行为 |
| --- | --- |
| 不内置 catalog-only | 无关键词参数（AzuraCast）或只有网页链接（WordPress/中文 API）都不保存为可搜索源 |
| 不绕过认证 | 401/403、Subsonic failed、Jellyfin API key 都明确提示，不尝试爆破/伪造 |
| 不保存歌曲数据 | 结果文件只存状态、数组路径、字段名、计数，不存标题/播放地址/凭据 |
| 不解析 XML | Subsonic 必须 `f=json`；XML 只做失败归类 |
| 不把试听当完整曲目 | iTunes `previewUrl` 仍是试听；UI/用户需知道时长由源站决定 |
| 不保证所有音乐 API 可用 | Funkwhale/Jellyfin/Ampache 匿名接口普遍失败；Deezer/Openverse/Mixcloud 本网络超时 |
| 同 host 多接口 | 源 ID 用 `origin + sitePath` 哈希，避免 `/rest/search3` 与 `/rest/search2` 互相覆盖 |
